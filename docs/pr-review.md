# PR review: gh-dash, herdr-pickr, tuicr

Snapshot: 2026-10-14 (herdr 0.9.4, herdr-pickr 0.1.2 at `e393ef5`, tuicr 0.27.0, gh-dash 4.26.1).

## Entry points

- **gh-dash** (`gh dash`): `t` on a PR row runs `tuicr pr <url>` in gh-dash's own pane; `T` runs `review-worktree <url>` (below); `S` runs `pr-agent <url>`, which sends one of your own PRs to an agent to fix it (below). `T` and `S` need gh-dash running inside herdr. The bindings are in `gh-dash/.config/gh-dash/config.yml`; `t` shadows gh-dash's own smart-filtering toggle.
  - `E` requests reviewers, which gh-dash has no action for (its `a` sets assignees). `gh-dash/.config/gh-dash/bin/request-reviewers` lists GitHub's suggested reviewers (★), then everyone who can be requested on the repo, then the organisation's teams, leaving out the author and anyone already requested. `tab` marks several, Enter runs `gh pr edit --add-reviewer`. It only adds reviewers; remove one on GitHub or with `gh pr edit --remove-reviewer`.
  - `C` and `space` replace gh-dash's built-in checkout, which runs `gh pr checkout` in the main checkout and so switches its branch. `gh-dash/.config/gh-dash/bin/checkout-pr` runs `wt switch <PR URL>` in the repo instead: the PR's own branch in its own worktree under `~/dev/wt/<owner>/<repo>/` (for fork PRs worktrunk fetches `refs/pull/N/head` and points the branch's push remote at the fork), with the repo's worktrunk hooks, then `herdr worktree open`, so the [worktree layout](herdr-workspaces.md#worktree-layout) applies; pressing it again focuses the open workspace. worktrunk asks before running a project's hook commands the first time and whenever they change, which includes a PR changing `.config/wt.toml`. The repo is found through gh-dash's `repoPaths` (`":owner/:repo": ~/dev/github.com/:owner/:repo`); a repo not cloned there yet can be cloned on the spot. Outside herdr it prints the worktree path instead.
- **herdr Ctrl+click** on a `https://github.com/<owner>/<repo>/pull/<N>` link opens the [herdr-pickr](https://github.com/tomasvarga/herdr-pickr) chooser overlay. Rows come from `herdr/.config/herdr/plugins/config/pickr/config.toml`:
  - `t` — `tuicr pr <url>` in the overlay. The overlay closes when tuicr quits.
  - `a` — `review-worktree <url>`: PR worktree workspace with its agent beside tuicr (below).
  - `o` — browser. pickr claims PR links, so Ctrl+click no longer opens the browser by itself.

Install pickr with `herdr plugin install tomasvarga/herdr-pickr`, then `stow --target="$HOME" herdr` for its config. Link clicks need `ui.mouse_capture = true` (already set).

## Agent-assisted review (`a`)

`review-worktree` (next to the pickr config):

1. Finds a checkout of `<owner>/<repo>` that is already open in herdr: any workspace's repo root or pane cwd with a GitHub remote for the repo. With none open it fails with "open one in a workspace first"; it never clones.
2. Fetches `refs/pull/<N>/head` and the base branch from that remote.
3. Marks `pr-<N>` as a PR review (`git config branch.pr-<N>.herdrReviewUrl <url>`), then opens a herdr worktree workspace on local branch `pr-<N>` at the PR head, labelled `<repo>#<N>`.
4. Waits for the `worktree-layout` hook to lay it out ([herdr-workspaces.md](herdr-workspaces.md#worktree-layout): agent | review / shell, agent from that plugin's config), presses enter in the review pane, which opens `tuicr pr <url>` because of the marker, and prompts the agent with the PR, the base, the tuicr session slug `gh:<owner>/<repo>/pr/<N>`, and how to read (`tuicr review comments`) and add (`tuicr review add --username <agent> --type … --side …`) draft comments. The prompt follows upstream tuicr's agent skill (`skills/tuicr/SKILL.md` in agavra/tuicr), including its warning that a line comment outside the diff is stored but never shown.

Re-running for the same PR focuses the open workspace, or reopens the worktree (laid out again by the hook) if its workspace was closed. A clean worktree is reset to the current PR head; one with local changes is left alone, with a notification. A leftover `pr-<N>` branch without a worktree is repointed, because that name is reserved for review worktrees. Nothing removes worktrees; run `herdr worktree remove --workspace <id>` when done.

Comments the agent adds with `tuicr review add` show up in the open tuicr without `:e` and survive tuicr's `:w` (smoke-tested). Comments you type in tuicr reach the agent through `tuicr-send` (below) or when it reads the session. `:w` first so they are saved.

## Sending your PR to an agent to fix (`S`)

`pr-agent` (next to review-worktree, sharing `pr-lib` with it) takes only your own open, same-repo PRs, and refuses others before touching anything.

1. An fzf picker offers three jobs; its preview is the exact prompt:
   - **conflicts**: `git merge <remote>/<base>` (never rebase), resolve keeping both sides' intent, run the project's checks, commit the merge, summarise each file.
   - **comments**: read unresolved review threads (`gh api graphql` `reviewThreads` with `isResolved`, `isOutdated`, `path`, `line`, comments) and reviews, plus `gh pr view --comments`; address each, commit, then run `show-in-review "$(git merge-base <remote>/<base> HEAD)..HEAD"` and add one tuicr comment per thread at the changed line (or the line the thread is about, when nothing changed): the reviewer's comment quoted, what changed in which commit or why not, and a draft reply. It then waits for you to say which replies to send.
   - **ci**: `gh pr checks`, `gh run view <id> --log-failed`, reproduce locally, fix, verify the same way; flaky or infrastructure failures are reported, not patched. Watch the rerun with `gh enhance <url>`.
2. Finds the checkout of the repo open in herdr (as review-worktree does), fetches the head and base branches, and looks for a worktree already on the PR's head branch.
3. With agents running in that worktree, `agent-pick --cwd <worktree> --new …` lists them plus "new agent". With none, no picker. A new agent comes from the `worktree-layout` hook when the workspace has to be opened: the worktree is reopened if its workspace was closed, or created on the head branch (an existing local branch as it is, otherwise branched from `<remote>/<head>` and tracking it), and pr-agent waits for the layout and prompts its `agent` pane. When the worktree's workspace is already open, the hook doesn't run, so the new agent starts in a new tab, named `<job>-<N>`, with the same kind (`agent` in the worktree-layout config).
4. An idle or done agent gets the prompt and is focused. A working or blocked one is focused and a herdr notification says the prompt was not sent; press `S` again when it is free.

Every prompt tells the agent to stop if it is not on the head branch, if the tree has uncommitted changes, or if the branch has diverged from the remote (fast-forward only when behind); to commit new commits only (no amend, rebase, or force); and not to push or write anything to GitHub. Only regex-validated identifiers (repo, number, branch names) go into it; descriptions, review comments, and CI logs are other people's text, read by the agent and to be treated as data.

`show-in-review <range>` (next to pr-agent) is what the comments job runs to present its work. It opens `tuicr -r <range>` in the `review` pane of the agent's workspace when that pane is at its menu or a shell prompt (pressing `q` to leave the menu first, and running the menu again after tuicr exits), or in a split to the agent's right when the workspace has no review pane. A review pane that is already running tuicr or anything else is left alone; the agent is told to ask you to free it. It prints the session slug (from tuicr's `active_sessions.json`, by pid) for `tuicr review add`.

Smoke-tested in throwaway herdr sessions from gh-dash on a private repo of yours (no pushes or GitHub writes). `S`: a new worktree (hook agent prompted), a reopened worktree (same), an open workspace's idle agent picked and prompted, "new agent" in an open workspace (new tab), the working-agent refusal, the picker leaving out a concurrent `pr-<N>` review agent, and the refusal for someone else's PR (the last three before the worktree-layout rework). `show-in-review`: run by the agent from the review pane's menu, refused while tuicr was open there, from a plain-shell review pane, and as a split in a workspace without one; the menu came back when tuicr quit. `T` and pickr's `a`: a new review, two at once, focusing an open one, and reopening a closed one, each with `tuicr pr` in the review pane and the agent prompted. Not exercised: a fork PR and a blocked agent (same path as working). The PR had no review threads, conflicts, or failing checks, so the agents only confirmed there was nothing to do; drafting tuicr comments was checked by hand.

## Sending review comments to an agent

Two local plugins in `herdr/.local/share/herdr-plugins/`, linked once with `herdr plugin link ~/.local/share/herdr-plugins/<name>`:

- **agent-pickr**: `bin/agent-pick` lists running agents (`herdr agent list`) in fzf and prints the chosen pane id. The layout follows telescope: a titled prompt (`--title`) over the results, with a `--header` inside the results frame and key hints in a `--footer`, on the left; on the right, the highlighted agent's status, directory, and recent output, titled `agent · workspace`. Rows show a status glyph (● working, ● blocked in red, ○ idle, ✓ done), the agent, its workspace, and its pane id. `--default <pane>` (or `$AGENT_PICKR_TARGET`) is listed first, preselected, and marked `*`; `--expect` passes fzf's accept keys through; `--cwd <dir>` keeps only agents in or below that directory; `--new <text>` adds a last row that prints `new` (pr-agent's "new agent"). Colours come from `FZF_DEFAULT_OPTS`. The `jump` action (`prefix+a`) opens it in a 90%×80% popup and focuses the pick.
- **tuicr-send** (`prefix+t`, with the tuicr pane focused): opens a popup that finds that tuicr process's session through `~/.local/share/tuicr/reviews/active_sessions.json` (pid to slug), reads `tuicr review comments`, and runs `agent-pick`. The default target is `AGENT_PICKR_TARGET` from the tuicr process environment (`/proc/<pid>/environ`, so Linux only). review-worktree sets it, so in the side-by-side layout Enter goes to the attached agent. From gh-dash or a pickr `t` overlay there is no default, so you choose. Enter submits (`herdr agent prompt`, rejected if the agent is blocked on a question); ctrl-y pastes into the agent's input without submitting (bracketed paste via `pane send-text`) and focuses it.

Comments go as one numbered message: `location [type] (author)`, then the text. Each agent terminal gets a comment only once, unless its text changes; the record is kept per session and agent terminal in `~/.local/state/herdr/plugins/tuicr-send/sent/`. When every comment was already sent, it asks before sending them all again.

Smoke-tested in a throwaway herdr session: default preselection from the tuicr environment, paste-only into a second agent, the re-send prompt, sending only a newly added comment, the action-to-popup environment handoff, and the error for a pane that isn't running tuicr. The popup UI itself can't be driven without an attached client, so its fzf was exercised from an ordinary pane running the same script.

Risks:

- The PR's code, docs, and repo-local agent instructions (e.g. `AGENTS.md`, `.omp/`) are attacker-controlled for outside contributors, and the agent runs inside that checkout. The prompt tells it to treat the PR as untrusted, not to run its code, and never to post, approve, or push. That is an instruction, not a sandbox.
- Only regex-validated identifiers go into the prompt. The PR title and body stay out; the agent reads them itself.
- pr-agent's agents work with write intent in your own branch, so it refuses PRs you didn't author and fork PRs. Review comments and CI logs still come from other people and tools; the prompt says to treat them as data, which again is an instruction, not a sandbox. Nothing stops the agent from pushing except that instruction.

## Decisions

- **Worktree + side-by-side agent over sniffr.** [herdr-sniffr](https://github.com/tomasvarga/herdr-sniffr) runs a one-shot background agent that injects draft comments into tuicr. Rejected: no conversation with the agent, no checkout for it to read beyond the diff, and its herdr launcher splits from the pane it runs in, which is pickr's temporary overlay.
- **tuicr's session store as the shared channel**: both sides read and write the same persisted session, so the agent can always catch up on its own. `tuicr-send` is the explicit push on top, because agents don't poll on their own; upstream's skill says to poll every ~30s only while waiting on a review.
- **tuicr-send gets its default target from an environment variable rather than plugin state**: the tuicr pane carries its own target, so nothing has to map tuicr panes to agents or clean that mapping up. The cost is the Linux-only `/proc` read.
- **agent-pickr is a separate plugin**, so `agent-pick` can be reused by other tools (gh-dash, pickr rows) to target an agent.
- **persiyanov/herdr-reviewr uninstalled.** It auto-opened a third pane in every new worktree, including review workspaces, and duplicated tuicr for PRs.
- **Review branch `pr-<N>`** (same convention as tdi/herdr-worktree-from-pr and tferreira/herdr-pr-ops) rather than the PR's head branch name. It avoids colliding with a local branch of the same name and works for fork PRs.
- **One `S` key with a job picker** rather than a key per job (`M`/`F`/`B` were free): one thing to remember, and the preview shows the exact prompt before anything runs. Keys checked against gh-dash v4.26.1's `prKeys.go`/`keys.go`, which also bind `L`, `V`, `n`, and `ctrl+s` beyond the docs site.
- **Fix work happens in the worktree on the PR's head branch**, reusing one you already have (often with its agent still there), so `git push` just works afterwards. Rejected: reusing the `pr-<N>` review worktree and pushing `pr-<N>:<head>` (mixes a "never push, code is untrusted" agent with fix work and ignores your existing worktrees on the branch), and a separate `fix-pr-<N>` worktree (duplicates those worktrees and needs a refspec push). A review agent is never offered: `agent-pick --cwd` only lists agents in the head-branch worktree.
- **No ownership marker on the head branch.** aviralmansingka/dotfiles' `gh-dash-open-pr` records `branch.<b>.ghDashPr` in git config and refuses to update branches it didn't create. pr-agent never resets, moves, or rebases an existing branch or worktree, so there is nothing to protect; the agent fast-forwards only when the branch is merely behind.
- **Your own PRs only, no forks.** A maintainer-editable fork would need a fork remote and push target; you rarely get those, and your own checkout's `AGENTS.md` is trusted while a stranger's isn't.
- **Don't interrupt a busy agent**: focus it and notify. Rejected: pasting the prompt into its input unsent (an agent mid-turn may treat typed input differently) and starting a second agent in the same worktree (two agents editing one tree).
- **Merge, not rebase, for conflicts**: no force-push, and it matches gh-dash's `u` (update-branch merge commit).
- **No push and no GitHub writes**: you review and push. For review comments the agent instead presents the branch in tuicr with each thread quoted and a draft reply, so you see the diff next to the original comments and tell it which replies to send.
- **Review-comment fixes are shown as the whole branch against the PR's base, in the review pane** (`tuicr -r <merge-base>..HEAD`). Rejected: `tuicr pr <url>`, which renders GitHub's diff and so can't show unpushed commits (its remote threads are read-only anyway, and `tuicr review add` has no reply target, so drafted replies are local comments either way); only the fix commits (`<before>..HEAD`), which has no line to anchor a thread the agent declined or fixed elsewhere; the review pane's own enter, which diffs against the remote's default branch and so is wrong for stacked PRs; and a split of its own, which makes a fourth pane next to a review pane that's already there.
- **The worktree-layout hook owns the layout and the agent** for every worktree workspace the scripts create or reopen; they wait with `layout-wait` and prompt its `agent` pane. One agent setting, `agent` in the worktree-layout config, replaces pickr's `[review] agent`. Only pr-agent's new tab in an already-open workspace starts an agent itself, because no hook runs there.
